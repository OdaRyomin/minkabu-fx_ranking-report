# みんかぶFXランキングコンテンツ テンプレート

みんかぶFXのランキング評価データをもとに、FX会社向けの半期評価レポートを作成するためのテンプレートです。

このテンプレートには実データと生成済み成果物を含めていません。利用時は `input/` にCSVなどの元データを配置し、`output/` に下書きやHTMLレポートを生成してください。

## 概要

主な用途は以下です。

- 総合順位、公開用の総合点、カテゴリ別評価を整理する
- 上位社との差分や強み・改善余地を説明する
- MarkdownまたはHTML形式で、顧客向けに説明可能な半期評価レポートを作成する
- 同一フォーマットで複数のFX会社向けレポートを作成する

## ディレクトリ構成

```text
.
├── DESIGN.md
├── README.md
├── input/
│   └── .gitkeep
├── output/
│   └── .gitkeep
└── 使用skill/
    └── build-data-driven-reports/
```

## 主なファイル・ディレクトリ

| パス | 内容 |
| --- | --- |
| `DESIGN.md` | HTMLレポートのデザイン仕様。レイアウト、配色、情報設計を定義 |
| `input/` | 元データ配置用ディレクトリ。CSV、Excel、Markdownメモなどを配置 |
| `output/` | 生成物配置用ディレクトリ。下書き、HTML、PDF化用ファイルなどを配置 |
| `使用skill/build-data-driven-reports/` | レポート作成に使用するSkill定義 |

## 入力データの例

`input/` には、レポート作成に必要なデータを配置します。

想定するデータ例は以下です。

- 総合順位・公開用の総合点
- 内部確認用の点数・スコア合計（レポートには掲載しない）
- カテゴリ別スコア
- FX会社の基本情報
- スプレッド関連データ
- スワップ関連データ
- レビュー関連データ
- 更新履歴・変更情報
- 編集部メモ、補足コメント

## レポート作成の流れ

1. `input/` に対象期間のデータを配置する
2. 総合順位・公開用の総合点・カテゴリ別評価を確認する
3. 更新履歴や補足メモから、対象期間中の主な変化を抽出する
4. 上位社との差を、カテゴリ名だけでなく具体的なスペック・評価項目まで確認する
5. 対象会社向けのMarkdown下書きを `output/` に作成する
6. 必要に応じてHTMLレポートを `output/` に生成する
7. `DESIGN.md` に沿って、情報順・見た目・開示範囲を確認する

## デザイン方針

HTMLレポートは、FX会社のマーケティング担当者や事業責任者が短時間で評価背景を理解できるように設計します。

主な方針は以下です。

- 冒頭で総合順位、公開用の総合点、部門最高順位、直近改善を提示する
- 本文では、総合評価、競争ポジション、カテゴリ診断、評価ポイント、更新事項、編集部所見の順に説明する
- 上位社との差分は「情報提供」「ツール」などのカテゴリ名だけで終わらせず、ニュース提供数、需給情報、セミナー、チャート、アラート、アプリ機能などの具体項目で示す
- 色は意味で使い、過度な装飾やカテゴリごとの多色展開は避ける
- 詳細な配点テーブル、内部点、スコア合計、調整係数、内部補正ロジックは公開しない
- レポート本体には、元CSV名、ローカルパス、ドラフト表記、データ出典一覧、内部確認用の留意事項を掲載しない

詳細は `DESIGN.md` を参照してください。

## 顧客向け出力ルール

- 総合点は `total_score.csv` の公開用点数だけを使用する
- 内部点やスコア合計を、本文、表、グラフ、注記へ出さない
- KPIは「総合順位」「総合点」「部門最高順位」「直近改善」の4件を基本とする
- 部門最高順位は、対象会社が各種ランキング部門で最も高い順位を掲載する
- 「要補強」「改善余地」には、不足する機能、コンテンツ、対応状況を具体的に書く
- 比較の根拠として具体的なスペックや評価項目は示すが、配点、重み、係数、算出過程には言及しない
- 総合ランキングのレポートでは「総合力で勝負しない」「別の訴求軸へ絞る」と提案しない。既存の強みを維持しながら弱い評価領域を補い、総合順位を上げる方向で総括する
- レポートは別途説明しながら渡す前提とし、データ出典と内部向け注意事項は制作管理側に残す

## 公開・共有時の注意

このテンプレート自体には実データを含めていませんが、利用後にGitHubなどへ公開する場合は以下を確認してください。

- `input/` 配下に社外公開できないデータが含まれていないか
- `output/` 配下に顧客名、スコア、順位、契約条件、非公開メモが含まれていないか
- 報酬単価、内部補正ロジック、詳細配点などを誤って公開していないか
- ライセンスや権利表記を明記する必要がないか

## ライセンス

未定です。公開する場合は、利用範囲に応じてライセンスまたは権利表記を追加してください。
